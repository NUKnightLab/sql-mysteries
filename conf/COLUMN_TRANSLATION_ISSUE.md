# データベース列名の日本語化指示

このドキュメントは、SQL Murder Mystery データベースの各テーブルと列名を日本語化するかどうかを検討するための資料です。

## 凡例

**日本語化の推奨度:**
- 🔴 **必須**: ゲームプレイに直接影響する重要な列
- 🟡 **推奨**: 日本語化すると理解しやすくなる列
- 🟢 **オプション**: 日本語化してもしなくても良い列
- ⚪ **不要**: 日本語化しない方が良い列（固有名詞、ID等）

## 日本語化の方針案

### 方針A: 最小限の日本語化（推奨）
- **テーブル名**: 英語のまま
- **列名**: 重要なもの（🔴 必須）のみ日本語化
- **メリット**: SQLの基本を学べる、互換性が高い
- **デメリット**: 完全に日本語化されない

**例:**
```sql
SELECT * FROM crime_scene_report
WHERE 種類 = '殺人' AND city = 'SQL City';
```

### 方針B: 積極的な日本語化
- **テーブル名**: すべて日本語化
- **列名**: ID以外はすべて日本語化（🔴🟡 必須・推奨）
- **メリット**: 完全に日本語で学習できる
- **デメリット**: 実際のSQLとの乖離、タイピングが面倒

**例:**
```sql
SELECT * FROM 犯罪現場レポート
WHERE 種類 = '殺人' AND 都市 = 'SQL City';
```

### 方針C: ハイブリッド（バランス型）
- **テーブル名**: 英語のまま
- **列名**: 🔴必須 + 🟡推奨 を日本語化
- **ID系**: すべて英語のまま
- **メリット**: バランスが良い
- **デメリット**: 一貫性がやや欠ける

**例:**
```sql
SELECT * FROM crime_scene_report
WHERE 種類 = '殺人' AND 都市 = 'SQL City';
```

## 推奨事項

**初心者向けゲームとしては「方針C: ハイブリッド」を推奨します。**

**理由:**
1. テーブル名は英語のままの方が、実際のSQLに近い
2. 重要な列（ゲームプレイに直結）は日本語化することで理解しやすくなる
3. ID系は英語のままの方が自然
4. バランスが取れている

**具体的な日本語化対象:**
- 🔴 必須: type, description, eye_color, hair_color, gender, membership_status, transcript
- 🟡 推奨: date, city, age, height, event_name, check_in_date, check_in_time

**日本語化しない:**
- すべてのID（id, person_id, event_id, license_id, ssn）
- 固有名詞（name, address_street_name, plate_number, car_make, car_model）
